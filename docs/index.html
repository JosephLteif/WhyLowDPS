Control by design

Know where your data lives.

In the Windows app, credentials, profiles, routes, history, and simulations stay on your machine. Light Mode lets you use supported local workflows without connecting an account.

A private hosted instance keeps each allowed Battle.net user’s data separate on the operator-controlled server. Hosted administrators can allow users, assign administrators, disable access, and revoke active sessions.

Network requests are used for Blizzard game data, GitHub releases and published updates, and documented external data sources. WhyLowDPS is independent and is not affiliated with Blizzard Entertainment, SimulationCraft, or Raidbots.

FAQ

Answers before you choose a setup.

Do I need a Battle.net API key?

No. Light Mode supports manual SimC, local analysis, history, upgrade planning, and content-reference workflows without credentials.

What does connecting Battle.net add?

Connected Mode adds account-aware character context such as rosters, saved characters, Great Vault data, wishlists, and talent tools.

Can I run WhyLowDPS as a private web app?

Yes. The release Docker deployment packages the web app, backend, and Linux SimulationCraft runtime for private single-instance hosting. for the deployment steps and callback rules.

Can I install the hosted app on my phone?

Yes. The hosted web app can be installed as a PWA when the deployment uses trusted HTTPS. The desktop app can also pair phones directly over a trusted private LAN.

Does WhyLowDPS run simulations locally?

The Windows desktop app runs SimulationCraft locally on your machine. A Docker-hosted deployment runs its own Linux SimulationCraft runtime on the private host.

Is WhyLowDPS affiliated with Blizzard or Raidbots?

No. WhyLowDPS is an independent project and is not affiliated with Blizzard Entertainment, SimulationCraft, or Raidbots.

Windows desktop

Install and choose your first mode.

  1. Download the latest completed Windows x64 release.Use the official GitHub release page and verify its checksum if you want to validate the installer.
  2. Choose Light Mode or connect Battle.net.Light Mode supports manual SimC, local analysis, history, upgrade planning, and shared catalogs. Connected Mode adds rosters, saved characters, Great Vault data, wishlists, and account-aware tools.
  3. Let the app prepare its data and runtime.Review simulation settings, then start with a small Quick Sim before a larger matrix or route simulation.
Battle.net callback

For the installed app, register http://localhost:17384/api/auth/bnet/callback in the Battle.net Developer Portal. Use the value labeled Client ID, not the management identifier in the portal URL.

Private Docker + PWA

Run your own private instance.

  1. Use an amd64 Linux host or Docker Desktop with WSL2.Arm64 is not currently supported because the companion SimulationCraft runtime is published for linux-x64.
  2. Pin the release and configure the host.Set the private host IP, client-facing port, unique JWT secret, session encryption key, and bootstrap administrator BattleTag. Keep the persistent whylowdps-data volume and secrets backed up.
  3. Pull and start with the environment file.Use docker compose --env-file .env.docker pull, then docker compose --env-file .env.docker up -d. Open the host address from the trusted LAN and add other allowed users from Manage Users.
Hosted OAuth and updates

Register the exact browser-facing callback: http://<HOST-IP>:<PORT>/api/auth/bnet/callback, or https://<HOSTNAME>/api/auth/bnet/callback behind trusted HTTPS. The scheme, hostname, port, and path must match.

Pin a release image for predictable rollback. Recreate the service after changing environment values or the image; docker compose restart app does not apply either change.

The PWA requires browser-trusted HTTPS. Direct LAN HTTP stays private but does not provide a secure browser context for native installation.

Trusted LAN sharing

Pair a phone without exposing the app.

  1. Put the PC and phone on the same trusted private network.Use a Windows Private network profile. Allow TCP port 17384 on the Private network only; never create a Public-network rule or port-forward it.
  2. Enable Share over LAN in Desktop Settings.Open Settings > Simulation, enable Share this app over LAN, and restart WhyLowDPS when prompted.
  3. Create and consume a one-time pairing link.Select New pairing link, scan the QR within five minutes, and choose Continue in Safari, Chrome, or another full browser if the scanner opens an embedded preview.
Access lifecycle

Keep the desktop app running while the phone is connected. Browser access expires after 24 hours; New link restores a device, Rename identifies it, and Remove access immediately returns it to the QR pairing screen.

Desktop LAN sharing is separate from Docker hosting. It uses the current desktop session and does not provide internet-facing access.
